# ml-python — difficulty service (FastAPI MLOps)

Python 3.12 FastAPI service that turns aggregated player telemetry into
personalised difficulty parameters for SUBB SURFERS (start speed, speed
ceiling, obstacle density, coin density, difficulty tier).

## API

| Method | Path                  | Description                                     | Codes |
| ------ | --------------------- | ----------------------------------------------- | ----- |
| GET    | `/healthz`            | Liveness + loaded model version/mode            | 200   |
| POST   | `/api/v1/difficulty`  | Predict difficulty from `PlayerTelemetry`       | 200/422 |

Interactive docs: `GET /docs` (Swagger UI) and `GET /redoc`, generated by
FastAPI.

### Example

```bash
curl -s -X POST http://localhost:4002/api/v1/difficulty \
  -H 'Content-Type: application/json' \
  -d '{
        "avg_speed": 18.4,
        "coins_per_run": 62.5,
        "crash_rate": 0.31,
        "session_length_min": 22.0,
        "runs_last_7d": 47
      }'
```

```json
{
  "speed_start": 10.736,
  "speed_max": 21.443,
  "obstacle_density": 0.703,
  "coin_density": 0.861,
  "difficulty_label": "hard",
  "model_version": "v1.0.0"
}
```

## The MLOps loop

```
 ml/train_difficulty_model.py                app/difficulty.py
 ┌──────────────────────────────┐   joblib   ┌─────────────────────────┐
 │ synthesize 6000 profiles     │ ────────▶  │ FastAPI :4002           │
 │ GradientBoostingRegressor    │  bundle    │ falls back to heuristic │
 │ metrics.json + model commit  │            │ if artifact is missing  │
 └──────────────────────────────┘            └─────────────────────────┘
        ▲                                             │
        └── .github/workflows/mlops.yml retrains weekly,
            commits the fresh model back to the repo, and a
            service restart hot-reloads it (model loads at startup).
```

- **Training**: `ml/train_difficulty_model.py` is fully self-contained — it
  synthesizes 6000 correlated player profiles with numpy, fits a
  `GradientBoostingRegressor` (difficulty score 0..1), prints a classification
  report over the banded labels, and writes both artifacts below.
- **Artifacts (committed to the repo)**:
  - `ml/models/difficulty_model.joblib` — bundle `{"model", "features",
    "model_version", ...}`.
  - `ml/metrics.json` — `r2`, `mae`, per-feature importances, `trained_at`
    (UTC), `model_version`.
- **CI**: `.github/workflows/mlops.yml` re-runs training weekly and commits the
  refreshed artifacts back; deploying the new model is a plain service restart,
  because the model is loaded once at startup (FastAPI lifespan).
- **Fallback**: if the joblib bundle or metrics file is missing/corrupt, the
  service serves the deterministic heuristic (`heuristic-v0`) so the endpoint
  never fails closed. Inference errors also degrade to the heuristic per-request.

## Run locally

```bash
cd services/ml-python
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
python ml/train_difficulty_model.py     # (re)generate model + metrics
python -m pytest tests/ -q              # unit tests
python -m uvicorn app.main:app --port 4002
```

## Docker

```bash
docker build -t subb/ml-python .
docker run --rm -p 4002:4002 subb/ml-python
```

Non-root user, `HEALTHCHECK` against `/healthz`, port from `PORT` (default 4002).
